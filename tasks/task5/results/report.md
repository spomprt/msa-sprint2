# Task 5: Istio Canary Routing с Fallback

## Архитектура решения

```
Client Request
     │
     ▼
┌─────────────────┐
│ Istio Proxy    │
│ (Sidecar)      │
└─────────────────┘
     │
     ▼
┌─────────────────┐
│ VirtualService  │
│ - Feature Flag  │
│ - Canary 90/10 │
│ - Retry Policy │
└─────────────────┘
     │
     ▼
┌─────────────────┐
│ DestinationRule │
│ - Subset v1    │
│ - Subset v2    │
│ - Outlier Det. │
└─────────────────┘
     │
     ▼
┌─────────────────┐
│ Services        │
│ v1 (90%)       │
│ v2 (10%)       │
└─────────────────┘
```

## Ключевые особенности

### Канареечная маршрутизация

- **90% трафика** направляется на версию v1
- **10% трафика** направляется на версию v2
- **Feature flag** маршрутизация приоритетна над canary

### Fallback логика

- **Retry политика**: 3 попытки с таймаутом 2s
- **Автоматический fallback**: при ошибках v1 трафик идет на v2
- **Outlier detection**: автоматическое исключение нестабильных endpoints

## Результаты

1. **Безопасный rollout**: постепенное развертывание новых версий
2. **Отказоустойчивость**: автоматический fallback при ошибках
3. **Гибкость**: легко изменить распределение трафика
4. **Мониторинг**: полная видимость маршрутизации
5. **Feature flags**: поддержка условной маршрутизации
